SocrAItic Circle: Multi-Agent LLM Debate & Evaluation

SocrAItic Circle is a multi-agent LLM debate framework where agents prepare, rebut, and are scored by judge modules built on argumentation theory. It was later rebuilt as a fully local LangGraph and MCP system, with hybrid-retrieval evidence grounding and failure-mode instrumentation that caught nine silent defects.
  • Adversarial Preparation: An invisible preparation phase lets agents check evidence, map arguments and anticipate weaknesses before the visible rounds, with persistent memory that mirrors how human debaters research.
  • Seven-Dimension Judges: Judge modules grounded in Toulmin's Model, Pragma-Dialectical Theory and the Elaboration Likelihood Model score seven weighted dimensions. Argument quality improved across the board, most on strategic merit (44%) and logical consistency (37%).
  • YAML Orchestration: Prompts and phase guidance live in YAML, separate from code, so theoretical frameworks can be swapped without code changes. This gave 15-20x faster iteration.
  • Multi-Phase Debate Flow: Debates run through preparation, targeted adversarial rebuttal and meta-consensus evaluation, with the judges' perspectives combined by weighted multi-dimensional scoring.
  • Ollama Local Deployment: Runs heterogeneous local models (Mixtral, DeepSeek R1, Phi4, Llama 3.1), with hierarchical storage for debate histories, experiment configs and prompt versions.
  • Graph Orchestration: A LangGraph state machine with 13 nodes feeds 16 parallel judge tasks through gate, cycle and Send fan-out patterns. Checkpoint resume was proven against a forced crash.
  • MCP Protocol Layer: Two MCP servers expose 9 tools and 7 resources, with stdio and HTTP transport equivalence proven live. HTTP overhead measured about 1.5x, against 194x for a cold stdio subprocess.
  • MLX Memory Residency: Debaters and judges are never loaded at the same time, so about 34 GB of model weights fit in 24 GB of memory. Prompt caching and batch_generate were measured and rejected.
  • Hybrid Evidence Retrieval: BM25, dense embeddings and RRF fusion over 14,195 documents compress about 8,262 retrieved tokens to about 150 per debater. On nDCG@10, hybrid retrieval lost narrowly to plain BM25 (0.6334 vs 0.6413).
  • Failure-Mode Instrumentation: Every generation is classified at the model boundary (EMPTY, TRUNCATED, MARKER_LEAK, PARSE_FAIL), which caught 9 defects that ran cleanly but produced wrong output. 63 of 70 pre-registered gates passed.

technical details

  • Judge weights: logical consistency 0.25, factual accuracy 0.20, rhetorical effectiveness 0.15, strategic merit 0.15, ethical conduct 0.10, belief-shift potential 0.10, audience engagement 0.05
  • Argument quality gains: strategic merit 44%, logical consistency 37%, rhetorical effectiveness 19%, factual accuracy 16%
  • Model residency: debaters 17.2 GB and judges 16.6 GB, never loaded together
  • Rejected optimizations: prompt caching (-5.2% TTFT) and batch_generate (3 failures across 2 architectures)
  • LangGraph recursion limit derived in code: 72 for a 5-round debate
  • Anomaly classes: EMPTY, TRUNCATED, MARKER_LEAK, PARSE_FAIL, DIMENSION_MISMATCH
  • Validity gates: temperature-0 paired ablations, with a run voided on identical transcript hashes across arms or zero citations with evidence enabled
  • Codebase: 8,481 lines, 89 tests, ruff-clean, 4 executed notebooks, 15 documentation guides, 26-entry decision log
