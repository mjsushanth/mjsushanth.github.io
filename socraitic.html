SocrAItic Circle: Multi-Agent LLM Debate & Evaluation

A multi-agent LLM debate framework with structured preparation, rebuttal and evaluation phases, scored by theory-informed judge modules that improved argument quality by 37% on logical consistency, 16% on factual accuracy, 19% on rhetorical effectiveness and 44% on strategic merit. It was then rebuilt as a fully local LangGraph and MCP system with hybrid-retrieval evidence grounding and failure-mode instrumentation that documented nine silent defects.
  • Adversarial Preparation: An invisible preparation phase lets agents check evidence, map arguments and anticipate weaknesses before visible rounds, backed by persistent memory that mirrors how human debaters research
  • Seven-Dimension Judges: Judge modules grounded in Toulmin's Model, Pragma-Dialectical Theory and the Elaboration Likelihood Model score seven weighted dimensions, from logical consistency (0.25) down to audience engagement (0.05)
  • YAML Orchestration: Prompts and phase guidance live in YAML, separate from code, so theoretical frameworks can be swapped without code changes, giving 15-20x faster iteration
  • Multi-Phase Debate Flow: Preparation, targeted adversarial rebuttal and meta-consensus evaluation, with the judges' diverse perspectives aggregated through weighted multi-dimensional scoring
  • Ollama Local Deployment: Heterogeneous local models (Mixtral, DeepSeek R1, Phi4, Llama 3.1) with hierarchical storage for debate histories, experiment configs and prompt versions
  • Graph Orchestration: LangGraph state machine with 13 nodes and gate, cycle and Send fan-out patterns feeding 16 parallel judge tasks, a derived recursion limit (72 for 5 rounds) and checkpoint resume proven against a forced crash
  • MCP Protocol Layer: Two servers exposing 9 tools and 7 resources, with stdio and HTTP transport equivalence proven live, HTTP overhead measured at 1.5x and a cold stdio subprocess at 194x
  • MLX Memory Residency: Debaters (17.2 GB) and judges (16.6 GB) are never co-resident, fitting ~34 GB of weights in 24 GB unified memory, while prompt caching (-5.2% TTFT) and batch_generate (3 failures across 2 architectures) were measured and rejected
  • Hybrid Evidence Retrieval: BM25, dense embeddings and RRF fusion over 14,195 documents, compressing ~8,262 retrieved tokens to ~150 per debater, where hybrid retrieval lost to plain BM25 (0.6334 vs 0.6413 nDCG@10)
  • Failure-Mode Instrumentation: Every generation is classified at the model boundary (EMPTY, TRUNCATED, MARKER_LEAK, PARSE_FAIL), catching 9 defects that ran cleanly but were wrong, with 63 of 70 pre-registered gates passed and 89 tests
